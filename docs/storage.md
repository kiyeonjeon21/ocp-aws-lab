[README](../README.md) 는 지금 구성을, 이 문서는 **왜 지금 구성이고 언제 바꾸는지**를 다룹니다.

## 언제 막히나

### RWX 가 필요해지는 순간

`manifests/50-rhoai/10-model-storage.yaml.tpl` 에 이미 적어 둔 제약입니다.

> KServe 스토리지 이니셜라이저와 서빙 파드가 같은 노드에 있어야 합니다.
> 여러 노드에서 붙이려면 RWX 가 필요하고, AWS 에서는 EFS 를 붙여야 합니다.
> 랩에서는 GPU 노드가 1대뿐이라 RWO 로 충분합니다.

**GPU 노드를 2대로 늘려 vLLM 을 2개 띄우는 순간 걸립니다.**
15GB 가중치를 노드마다 따로 복사하든지, RWX 를 붙이든지 해야 합니다.

같은 이유로 걸리는 것들이 더 있습니다.

- Jupyter 워크벤치 여러 개가 같은 데이터셋을 봐야 할 때
- 서빙 파드를 여러 개 띄워 같은 모델을 공유할 때
- CI 아티팩트, 공유 로그

### S3 가 필요해지는 순간

RHOAI 의 Data Science Pipelines 는 S3 를 요구합니다.
모델 레지스트리와 MLflow 아티팩트도 마찬가지입니다.

AWS 에서는 그냥 S3 를 쓰면 됩니다. 내부 이미지 레지스트리도 이미 S3 를 씁니다.
**문제는 폐쇄망입니다.** 거기엔 S3 가 없습니다.

## 선택지 셋

| | 제공 | AWS 비용 | 언제 |
| --- | --- | --- | --- |
| `gp3-csi` | RWO 블록 | 이미 포함 | 기본. RWO 로 되면 여기서 끝 |
| **EFS CSI** | **RWX 파일** | 스토리지 $0.30/GB-월 + 처리량 | AWS 에서 RWX 만 필요할 때. **대개 이게 정답** |
| **ODF** | RWO + **RWX** + **S3** | **노드 3대 시간당 $2~3** | 온프렘/폐쇄망. 또는 S3 가 클러스터 안에 필요할 때 |

**AWS 에서 RWX 만 필요하면 ODF 는 과합니다.**
EFS 가 훨씬 싸고 오퍼레이터 하나로 끝납니다.

ODF 가 진짜 필요한 건 **클라우드가 안 주는 걸 클러스터가 스스로 만들어야 할 때**입니다.
그게 온프렘 베어메탈이고, 폐쇄망입니다.

## ODF 를 붙인다면

ODF 는 Ceph 를 OCP 안에서 돌립니다(Rook 오퍼레이터).

| 종류 | Ceph | 쓰임 |
| --- | --- | --- |
| 블록 RWO | RBD | 일반 PVC |
| 파일 RWX | CephFS | 여러 파드가 같은 볼륨 |
| 오브젝트 S3 | RGW / NooBaa | S3 API 를 클러스터 안에서 |

### 스토리지 전용 노드를 따로 두는 이유

배포 방식이 둘입니다.

1. **컴퓨트 워커에 같이** - 소규모. 워커가 앱과 Ceph OSD 를 같이 돌립니다
2. **스토리지 전용 노드** - `cluster.ocs.openshift.io/openshift-storage` 라벨 + taint. 별도 MachineSet

2번으로 가는 이유는 자원 격리입니다. Ceph OSD 는 양방향으로 성격이 나쁩니다.

- 앱이 CPU 를 다 쓰면 OSD 가 느려지고, **스토리지는 모두가 쓰므로 그 지연이 클러스터 전체로 번집니다**
- 디스크가 죽어 리커버리가 돌면 OSD 가 CPU 와 네트워크를 폭식해서 **같은 노드의 앱이 같이 느려집니다**

두 방향 다 예측이 안 되므로, 같은 노드에 두면 "왜 갑자기 느리지" 를 추적할 수 없게 됩니다.

그 외 이유들입니다.

- **장애 격리**: 앱 워커를 재부팅하거나 스케일다운해도 스토리지가 안 흔들립니다
- **스케일 축이 다름**: 컴퓨트 수요와 용량 수요는 따로 늡니다. 묶으면 한쪽 때문에 다른 쪽을 과다 구매합니다
- **인스턴스 타입이 다름**: 스토리지 노드는 로컬 NVMe(`i3en`, `m5d`)나 큰 EBS 를 씁니다
- **구독 비용**: 인프라 노드 분류에 따라 계산이 달라집니다. 조건이 계약마다 달라 Red Hat 에 확인할 항목입니다

### AWS 에서의 최소 구성

```text
ODF 전용 MachineSet 3대
  m5.4xlarge 이상 (16 vCPU / 64GB 권장)
  각 노드에 gp3 2TB 또는 i3en 로컬 NVMe
  AZ 3개에 하나씩            <- Ceph 기본 3 replica
```

**이 랩의 단일 AZ 구조와 맞지 않습니다.**
ODF 를 제대로 하려면 `ai` 프로파일부터 3 AZ 로 다시 짜야 합니다.

## 이 랩의 결론

**지금은 붙이지 않습니다.**

| 조건 | 판단 |
| --- | --- |
| RWO 만 필요 | `gp3-csi` 로 충분 |
| S3 필요 | AWS S3 가 이미 있음 |
| 단일 AZ | Ceph 3 AZ 분산과 안 맞음 |
| 비용 | 시간당 $2~3 추가. 지금 $1.84 의 2배 이상 |

붙일 만한 시점은 둘입니다.

1. **GPU 노드를 2대 이상으로 늘려 모델을 공유할 때** - 그때도 AWS 면 EFS 가 ODF 보다 싸고 간단합니다
2. **[ocp-airgap-lab](../../ocp-airgap-lab) 에서 S3 가 없을 때** - 이쪽이 진짜 ODF 가 필요한 케이스입니다

즉 **AWS 에서는 대개 안 붙이고, 폐쇄망에서 필요해집니다.**
폐쇄망 레포에서 다룰 주제입니다.
